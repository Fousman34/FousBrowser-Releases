# FousBrowser — Архитектура

Документ описывает устройство FousBrowser: состав компонентов, границы ответственности,
криптографию хранилища, жизненный цикл профилей, каналы обновлений, процесс сборки и
пользовательский интерфейс.

## 1. Назначение и границы проекта

FousBrowser — **десктопный лаунчер**, а не браузер. Он управляет управляемыми браузерными
профилями, запускает браузерные движки с нужными параметрами, шифрует все данные на диске
и проверяет обновления. Сам браузер («движок») поставляется **отдельно** от лаунчера и
обновляется по собственным каналам.

| Область | В проекте | Комментарий |
|---|---|---|
| Лаунчер | Да | Tauri 2: Rust-ядро + веб-фронтенд, установка, интерфейс, прокси, обновления |
| Хранилище | Да | Зашифрованные метаданные и данные профилей в пользовательской директории |
| Прокси-мост | Да | Локальный прокси, добавляющий учётные данные к апстрим-прокси |
| Обновления | Да | Три независимых канала: Normal-движок, Antidetect-движок, сам лаунчер |
| Журнал и восстановление | Да | Индекс, состояния, разбор осиротевших временных каталогов после краха |
| Код движка в v1.0 | Нет | Движок — внешний артефакт; собственный форк отнесён к Фазе B |
| Свой сетевой стек | Нет | Используется сеть Chromium и локальный прокси-мост |
| Анонимизация трафика | Нет | Лаунчер не VPN/Tor-клиент; за анонимность отвечает выбранный прокси |
| Гарантия недетектируемости | Нет | Antidetect снижает энтропию отпечатка, но гарантий не даёт |
| Восстановление пароля | Нет | Ключ выводится из пароля и нигде не хранится |
| Поддержка macOS | Нет | Экономия на Apple Developer ID, нотаризации и Gatekeeper |

Поддерживаемые платформы: **только Windows и Linux**. Лицензия: **PolyForm Noncommercial
License 1.0.0**. Единственный репозиторий: `github.com/Fousman34/FousBrowser-Releases`
(исходники и релизы в одном месте).

## 3. Выбор технологий

| Область | Решение | Обоснование |
|---|---|---|
| Оболочка | **Tauri 2** (Rust + веб-фронтенд) | Малый размер дистрибутива, криптография в Rust надёжнее и ближе к системным вызовам |
| Альтернатива | Electron — **отклонена** | Больший размер, крипто-часть в JS-окружении, лишний уровень доверия |
| Фронтенд | **Svelte 5 + TypeScript + Vite** | Малый рантайм, предсказуемая сборка, отсутствие тяжёлого фреймворка |
| Стили | **CSS-переменные / токены** | Единая тема, переключение акцентов без пересборки |
| Платформы | **Windows + Linux** | macOS исключён: экономия на подписи и нотаризации |
| KDF | **Argon2id** | Устойчивость к перебору на GPU/ASIC, настраиваемая стоимость |
| Шифр данных | **XChaCha20-Poly1305** | 24-байтовый nonce без риска коллизий, AEAD, без требований к аппаратному AES |
| Субключи | **HKDF** от мастер-ключа | Разделение доменов: метаданные, каждый профиль, файловые чанки |
| Гигиена памяти | `zeroize`, `mlock`/`VirtualLock` | Снижение времени жизни ключевого материала в памяти |
| Прокси-мост | **Rust + tokio** | Без внешних бинарей вроде `gost`, один процесс, контроль над логами |
| Проверка GPG | **sequoia-openpgp / rpgp** | Проверка подписи без требования установленного `gpg` у пользователя |
| Терминал и шрифт | **xterm.js**, **JetBrains Mono** в комплекте | Нет сетевых запросов при первом запуске, нет утечки факта запуска |
| CI/CD | **GitHub Actions**, `tauri-action` | Матрица Windows/Linux, публикация артефактов и манифестов |

## 4. Модули Rust-ядра

| Модуль | Ответственность |
|---|---|
| **Vault** | Открытие/закрытие хранилища, Argon2id, вывод мастер-ключа и субключей, verifier, авто-блокировка по неактивности, блокировка при «Остановить все профили», `zeroize` ключевых буферов |
| **ProfileStore** | CRUD профилей (Normal / Antidetect), привязка прокси, fingerprint-seed, клонирование (в том числе «без cookies/логинов»), состояние и сериализация метаданных |
| **CryptoFS** | Пофайловое потоковое шифрование чанками 1 МиБ, сборка AAD, расшифровка контейнера профиля во временную директорию, обратное шифрование, безопасное удаление копии |
| **EngineManager** | Выбор движка и версии, запуск процесса с `--user-data-dir` и набором флагов, запись PID и состояния в индекс, корректное завершение с таймаутом, kill дерева процессов |
| **ProxyBridge** | Подъём локального прокси на `127.0.0.1:<случайный порт>`, добавление учётных данных к SOCKS5/HTTP/HTTPS-апстриму, проверка доступности прокси, запрет non-proxied UDP |
| **UpdateService** | Три канала обновлений, расписание и джиттер, staging-каталог, проверка SHA-256 и GPG-подписи, minisign для лаунчера, атомарная подмена указателя, откат |
| **Journal / Recovery** | Ведение `index.json` и `attempts.json`, атомарная запись с `fsync`, счётчик неудачных попыток и нарастающая задержка, разбор записей `running`/`orphan` при старте |
| **IPC-слой** | Tauri commands от фронтенда и events к фронтенду |

События Rust → фронтенд: `vault://unlocked` (хранилище открыто, ключи выведены),
`profile://state` (`running`, `stopping`, `stopped`, `orphan`), `update://progress` (проценты
и скорость), `update://log` (строки в терминальное окно), `update://done` (доступна кнопка
«Перезапустить»). Обратное направление — команды: разблокировка хранилища, список профилей,
запуск/остановка/остановка всех, клонирование, правка прокси, ручная проверка обновлений,
отмена загрузки, перезапуск приложения.

## 5. Схема шифрования и раскладка хранилища

| Параметр | Значение |
|---|---|
| KDF | Argon2id, 256 МиБ памяти, 3 итерации, параллелизм 4 → 32-байтовый мастер-ключ |
| Соль | 16 байт, в открытом заголовке |
| Параметры KDF | Хранятся в заголовке — допускают изменение без ломки совместимости |
| Проверка пароля | AEAD-verifier: тег над известным плейнтекстом. Хеш пароля не хранится |
| Шифр данных | XChaCha20-Poly1305 |
| Nonce | 24 байта, случайный, на файл/чанк |
| AAD | Путь файла + номер чанка + UUID профиля (защита от перестановки и подмены) |
| Субключи | HKDF от мастер-ключа: для метаданных, для каждого профиля, для файловых чанков |

Неверный пароль приводит к ошибке аутентификации — ничего не расшифровывается, частичного
или «усечённого» чтения не происходит.

### Раскладка хранилища

Данные размещаются **в пользовательской директории, а не в папке установки**: Windows —
`%APPDATA%\FousBrowser`; Linux — `~/.local/share/FousBrowser` (профили) и
`~/.config/FousBrowser` (настройки).

```
FousBrowser/
  vault/
    header.json               ОТКРЫТЫЙ заголовок: сигнатура, версия формата, vault_id,
                              соль, параметры Argon2id, verifier (шифротекст)
    vault.enc                 зашифрованные метаданные (профили, прокси, настройки)
    attempts.json             ОТКРЫТЫЙ счётчик неудачных попыток входа
    index.json                ОТКРЫТЫЙ индекс: uuid, путь временной папки, статус (этап M5)
    profiles/
      <uuid>/                 зашифрованные данные профилей (этап M4)
    tmp/
      <uuid>/                 расшифрованная копия во время работы браузера (этап M4)
  browsers/
    normal/<версия>/          скачанный Normal-движок (этап M5)
    antidetect/<версия>/      скачанный Antidetect-движок (этап M8)
```

`header.json` не содержит секретов: соль и параметры Argon2id не являются тайной, а
`verifier` — это шифротекст, по которому можно лишь проверить правильность пароля.
Идентификатор `vault_id` из заголовка входит в AAD всех контейнеров, поэтому перенести
шифротекст в другое хранилище нельзя.

`index.json` содержит только uuid, путь временной папки и статус — без имён профилей,
настроек, прокси и отпечатков. `attempts.json` содержит число неудачных попыток и время
последней попытки — без данных профилей, ключей и паролей. Индекс нужен, чтобы после краха
понять, какие временные папки осиротели; открытым он сделан сознательно: до ввода пароля
ключа ещё нет, а без него шифровать нечем.

## 6. Жизненный цикл профиля

### Запуск

1. Запросить пароль, если ключа ещё нет в сессии.
2. Расшифровать контейнер профиля во временную директорию (этап v1) либо смонтировать
   шифрованную файловую систему (этап v2).
3. Поднять прокси-мост на `127.0.0.1:<случайный порт>`.
4. Запустить движок с `--user-data-dir`, указывающим на расшифрованную папку.
5. Записать состояние `running` и PID в индекс.

### Остановка

1. Корректное завершение процесса с таймаутом.
2. При необходимости — kill дерева процессов.
3. Шифрование временной папки обратно в контейнер профиля.
4. Безопасное удаление расшифрованной копии.
5. Состояние `stopped`, остановка прокси-моста.

### «Остановить все профили»

Одна кнопка, параллельная обработка всех запущенных профилей, прогресс по каждому, отчёт о
неудачах и повтор для завершившихся с ошибкой. Операция также инициирует блокировку
хранилища и очистку ключевого материала.

### Восстановление после краха

При старте всё, что в индексе помечено `running` или `orphan`, по настройке либо
**шифруется обратно**, либо **удаляется**. Выбор пользователя фиксируется в настройках.

### Два этапа работы с открытым текстом на диске

| Этап | Механизм | Открытый текст на диске |
|---|---|---|
| v1 | Пофайловое потоковое шифрование, чанки 1 МиБ, расшифровка в `vault/tmp/<uuid>/` | Присутствует во время работы браузера |
| v2 | Шифрованная ФС-обёртка: **FUSE** на Linux, **WinFsp/Dokany** на Windows | Отсутствует; копирование не требуется |

### RAM-диск

`/dev/shm` (tmpfs) доступен только на Linux. Используется, только если размер профиля
меньше 25% свободной памяти. Иначе применяется зашифрованный временный каталог на диске.

## 7. Прокси и прокси-мост

Прокси задаётся **на профиль**. Поддерживаемые схемы: SOCKS5, HTTP, HTTPS. Настройки,
включая логин и пароль, хранятся зашифрованными.

**Проблема:** браузерные движки не поддерживают парольную аутентификацию прокси через флаг
`--proxy-server`. **Решение:** лаунчер поднимает локальный прокси-мост на
`127.0.0.1:<случайный порт>`, который добавляет учётные данные к апстрим-прокси, а движку
отдаётся уже «беспарольный» локальный адрес. Выгоды: аутентификация выполняется там, где она
поддерживается; пароль прокси не попадает в список процессов и в логи командной строки;
реализация идёт на Rust (tokio), без внешних бинарей вроде `gost`; видно, куда реально идёт
трафик профиля.

Защита от утечек WebRTC: флаги политики обработки IP и запрет non-proxied UDP
(`--disable-non-proxied-udp` для Antidetect-сборок; для Normal — политика обработки IP).

## 8. Карта подмены fingerprint

| Параметр | Normal (стоковый Chromium) | Antidetect (Chromium + патчи) |
|---|---|---|
| User-Agent и Client Hints | Реальные, из версии движка | `--fingerprint` плюс подмена UA, Client Hints согласованы с ним |
| Canvas 2D | Не трогается | Патч шума/подмены (Фаза B) |
| WebGL vendor/renderer | Реальные | Патч vendor/renderer (Фаза B) |
| Audio | Реальный | Патч отпечатка аудиостека (Фаза B) |
| Шрифты | Системные | Подмена набора (Фаза B) |
| ClientRects | Реальные | Патч геометрии (Фаза B) |
| Timezone | Системная | `--timezone` + timezone через ICU (Фаза B) |
| `navigator.hardwareConcurrency` | Реальное | `--fingerprint-hardware-concurrency` |
| `navigator.plugins` | Стандартный набор движка | Патч списка плагинов (Фаза B) |
| Платформа и бренд | Реальные | `--fingerprint-platform`, `--fingerprint-brand` |
| WebRTC / IP | Политика обработки IP | `--disable-non-proxied-udp`, запрет non-proxied UDP |
| Отключаемость | — | `--disable-spoofing` для точечного отключения подмен |

Клонирование профиля даёт **новый fingerprint-seed**. Обязательна опция «клонировать без
cookies/логинов»: иначе копия сессии с другим отпечатком вызывает флаги у платформ.

## 9. Три канала обновлений и расписание

Каналы независимы и не смешиваются: у них разные источники, разные ключи проверки и разные
манифесты.

- **Канал A — Normal-движок.** Официальный JSON-манифест Chrome for Testing
  (`last-known-good-versions-with-downloads.json`) со SHA-256; вариант — Chromium-снапшоты.
  Порядок: скачивание → проверка хеша → распаковка в `browsers/normal/<версия>` → атомарная
  подмена указателя «текущая» → сохранение предыдущей версии для отката. Публичных
  Omaha-эндпоинтов для сторонних сборок Chromium не существует; протокол Omaha 3.1 открыт,
  поэтому собственный Omaha-совместимый сервер возможен, но отнесён к дальней дорожной
  карте — ответы защищены CUP, нужна своя ключевая пара.
- **Канал B — Antidetect-движок.** Источник:
  `https://api.github.com/repos/{owner}/{repo}/releases/latest`. Выбор asset по ОС и
  архитектуре, скачивание архива и отдельного файла `SHA256SUMS.asc`, проверка detached
  GPG-подписи встроенным публичным ключом (`resources/keys/`), проверка SHA-256, атомарная
  установка с откатом. **Несовпадение подписи = жёсткий отказ и запись в лог.** Проверка
  реализована на Rust (sequoia-openpgp или rpgp), без внешнего `gpg` у пользователя.
- **Канал C — самообновление лаунчера.** Встроенный апдейтер Tauri. Он проверяет
  **minisign**, а не GPG: это отдельная ключевая пара и отдельный `latest.json`. Каналы не
  смешивать.

Расписание: проверка при старте, далее каждые 6 часов (интервал, не кратный суткам), плюс
случайный джиттер 0–20% к интервалу, плюс ручная кнопка проверки в любой момент.

Интерфейс обновления: прогресс-бар с процентами и скоростью, поток логов в терминальном
окне, по завершении — экран «Обновление завершено» с кнопкой «Перезапустить». Отмена на
любом шаге не должна портить текущую версию: вся работа идёт в staging-каталоге, подмена —
атомарная.

## 10. План по фазам для движка Antidetect

| Фаза | Содержание | Срок |
|---|---|---|
| **A** | Пиннинг сборок проекта fingerprint-chromium (основа — ungoogled-chromium, лицензия BSD-3, атрибуция обязательна), зеркалирование в собственные GitHub Releases | Версия 1.0 |
| **B** | Собственный форк на базе ungoogled-chromium со своим набором патчей | После 1.0 |
| **C** | Self-hosted раннер и `sccache` для автоматизации сборок форка | После Фазы B |

Почему в Фазе A берётся именно fingerprint-chromium: готовые бинарники для Windows и Linux и
ровно нужные флаги — `--fingerprint`, `--fingerprint-platform`, `--fingerprint-brand`,
`--fingerprint-hardware-concurrency`, `--timezone`, `--disable-spoofing`,
`--disable-non-proxied-udp`. Почему Фаза B делается на ungoogled-chromium, а **не** на
fingerprint-chromium: у последнего исходники публикуются с задержкой около месяца после
бинарников, что несовместимо с собственным релизным циклом.

Набор патчей Фазы B: Canvas 2D, WebGL vendor/renderer, Audio, шрифты, ClientRects, timezone
через ICU, `navigator.hardwareConcurrency`, `navigator.plugins`, UA и Client Hints, политика
WebRTC.

Ключевые цифры по сборке Chromium:

| Метрика | Значение |
|---|---|
| Исходники Chromium | ~100 ГБ |
| Полная сборка | 4–8 часов |
| Инкрементальная сборка | 10–60 минут |
| Периодичность пересборки | ~каждые 4 недели, вслед за веткой Chromium |
| GitHub-hosted раннеры | **Не подходят**: 14 ГБ диска и лимит 6 часов |

В коде с самого начала закладывается абстракция `EngineProvider`, чтобы переход от зеркала
upstream к собственному форку был заменой одной реализации, а не переписыванием запуска.

## 11. CI/CD и артефакты

GitHub Actions, матрица `windows-latest` + `ubuntu-22.04`, триггер по тегу версии, сборка
через `tauri-action`, публикация в draft release. Отдельная джоба формирует `SHA256SUMS` +
GPG-подпись и `latest.json` для апдейтера.

| Платформа | Артефакты | Особенности |
|---|---|---|
| Windows | `.msi`, NSIS `.exe` | Установка per-user, без прав администратора |
| Linux | `.AppImage`, `.deb` | Сборка на `ubuntu-22.04` |
| macOS | Не собирается | Платформа исключена из поддержки |

Подпись Windows (Authenticode) **рекомендуется**, но при отсутствии сертификата README
описывает обход SmartScreen: предупреждение системы в этом случае — ожидаемое поведение.
Рабочие файлы: `.github/workflows/ci.yml` (проверки и сборка) и
`.github/workflows/release.yml` (тег, draft release, манифесты).

## 12. Интерфейс и анимация печати

Визуальный язык: тёмная терминальная эстетика, акценты зелёный/циан, **без градиентов** и
скруглённых «пузырьков», иконки line-art/ASCII. Шрифт — моноширинный **JetBrains Mono**,
поставляется вместе с приложением и не тянется из сети.

| Элемент | Реализация |
|---|---|
| Анимация печатающегося текста | `requestAnimationFrame` с накопителем времени, 18–25 мс на символ, ускорение на длинных текстах, мгновенное завершение по клику или Esc |
| Разбиение на символы | Итерация по графемам через `Intl.Segmenter`, а не по code units |
| Курсор | Отдельный элемент с CSS-анимацией мигания; продолжает мигать после окончания печати |
| Короткие заголовки | CSS-анимация `steps()` — только для однострочных заголовков; Typed.js и подобные библиотеки отклонены |
| Подсказки | Позиционируемая строка рядом с элементом, печатается посимвольно при наведении; системные тултипы не используются |
| Меню и переходы | Выпадающих меню нет: выезжающие панели и инлайн-раскрытие; переходы fade/slide, уважается `prefers-reduced-motion` |
| Логи | Терминальное окно на базе **xterm.js** (обновления и работа) |

### Оформление запущенного профиля

| Элемент | Реализация |
|---|---|
| Стартовая страница | Своя страница из `resources/start/`: знак проекта, одна строка поиска (поиск уходит в Google), без чужих логотипов. Готовится в каталоге данных, открывается движком как `file://` |
| Заголовок окна профиля | `FousBrowser — <профиль>`; название движка вырезается из заголовка, в том числе локализованное: оно читается из ресурсов самого движка (`ProductName`), а не из списка брендов в коде |
| Значок окна и панели задач | Значок проекта, извлечённый из исполняемого файла лаунчера (`ExtractIconW`) и переданный окну через `WM_SETICON` |
| Имя окна в Linux | Флаг `--class=FousBrowser` |
| Вежливая остановка | `WM_CLOSE` главному окну (то же, что крестик): `taskkill` без `/F` движок не закрывает |


## 13. Структура репозитория

```
FousBrowser-Releases/
  launcher/            src-tauri/ (Rust: vault, cryptofs, engine, proxy, updater), src/ (Svelte+TS),
                       resources/{icons,fonts,keys,licenses}
  browsers/            normal/, antidetect/ (скачиваемые движки, в git не хранятся)
  profiles/            зашифрованные профили (в git не хранятся)
  docs/                ARCHITECTURE.md, THREAT-MODEL.md, UPDATE.md
  .github/workflows/   ci.yml, release.yml
  LICENSE, README.md, THIRD_PARTY_NOTICES.md
```

В git хранятся `launcher/` (включая `src-tauri/`, `src/` и `resources/` с иконками, шрифтами,
публичными ключами и текстами лицензий), `docs/`, рабочие файлы CI и корневые `LICENSE`,
`README.md`, `THIRD_PARTY_NOTICES.md`. Каталоги `browsers/normal/`, `browsers/antidetect/` и
`profiles/` содержат скачанные движки и зашифрованные профили и в git не хранятся.

| **M9** | CI/CD: матрица, `tauri-action`, `SHA256SUMS`, GPG, `latest.json`, draft release | Воспроизводимый релиз на Windows и Linux | — |

## 15. Критерии готовности версии 1.0

- [ ] Хранилище открывается Argon2id (256 МиБ, 3 итерации, параллелизм 4); verifier отвергает неверный пароль без частичной расшифровки.
- [ ] Данные профилей зашифрованы XChaCha20-Poly1305 с AAD из пути, номера чанка и UUID профиля; перестановка чанков обнаруживается.
- [ ] Субключи разделены через HKDF; ключевые буферы зануляются, есть авто-блокировка по неактивности.
- [ ] Профили Normal и Antidetect запускаются, останавливаются и восстанавливаются после краха; «Остановить все профили» работает параллельно с отчётом о неудачах.
- [ ] Клонирование профиля даёт новый fingerprint-seed и умеет не переносить cookies/логины.
- [ ] Прокси SOCKS5/HTTP/HTTPS работает через локальный мост; пароль не попадает в командную строку и логи.
- [ ] Работают три независимых канала обновлений; несовпадение GPG-подписи — жёсткий отказ; minisign лаунчера не смешан с GPG движка; отмена не портит текущую версию.
- [ ] Политика попыток реализована полностью: инкремент до проверки пароля, `fsync`, сброс при успехе, задержки 5 с → 30 с → 2 мин → 10 мин → 1 ч, предупреждение на 90+, пауза на 100. **Автоудаления данных нет.**
- [ ] Восстановление после краха обрабатывает `running`/`orphan` по настройке.
- [ ] Интерфейс соответствует терминальной эстетике, печатающийся текст ускоряется и прерывается, `prefers-reduced-motion` уважается, шрифт поставляется локально.
- [ ] CI собирает `.msi`, NSIS `.exe`, `.AppImage`, `.deb` по тегу и публикует `SHA256SUMS` с подписью и `latest.json`.
- [ ] README, LICENSE (PolyForm Noncommercial 1.0.0) и THIRD_PARTY_NOTICES.md актуальны, атрибуция ungoogled-chromium (BSD-3) присутствует.
