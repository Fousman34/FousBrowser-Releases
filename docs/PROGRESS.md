# FousBrowser — журнал разработки

Файл существует ради устойчивости к сбоям: вся картина проекта живёт в git, а не в истории
переписки. Если сессия агента или разработчика оборвётся, работа продолжается с этого места.

## Состояние на этап M5

| Этап | Содержание | Состояние |
|---|---|---|
| M0 | Документация, каркас, лицензия | готово |
| M1 | Хранилище: Argon2id, XChaCha20-Poly1305, метаданные, вход | готово, 64 теста |
| M2 | Интерфейс: терминальная тема, печатающийся текст, иконки | готово |
| M3 | Профили: CRUD, клонирование с новым зерном, прокси | готово, проверено E2E |
| M4 | CryptoFS: шифрование данных профиля на диске | готово, 96 тестов |
| M5 | EngineManager: запуск, остановка, «остановить все профили», оформление | готово, проверено E2E (31 проверка) |
| M6 | ProxyBridge: локальный мост к SOCKS5/HTTP/HTTPS | следующий |
| M7 | Journal/Recovery: разбор осиротевших каталогов после краха | план |
| M8 | UpdateService: каналы Normal и Antidetect, проверка GPG | план |
| M9 | CI/CD: сборки, установщики, релиз | план |

## Что уже умеет лаунчер

1. Хранилище создаётся по мастер-паролю (Argon2id), список профилей и настройки прокси
   лежат в зашифрованных метаданных.
2. Профиль создаётся, клонируется (с новым зерном отпечатка), правится и удаляется
   вместе с данными.
3. Запуск профиля: данные расшифровываются во временный каталог, движок стартует с
   `--user-data-dir` на него, в `vault/index.json` появляется запись «работает».
4. Окно профиля оформляется как FousBrowser (заголовок и значок проекта), стартовая
   страница — своя, с одной строкой поиска.
5. Остановка: окну отправляется `WM_CLOSE`, после выхода процесса данные шифруются
   обратно в контейнер, расшифрованная копия затирается.
6. «Остановить все профили» — одна кнопка: все окна закрываются параллельно, данные
   каждого шифруются, неудачи перечисляются в интерфейсе.
7. Если профиль завершился сам (пользователь закрыл окно), сторож раз в 2 секунды
   замечает это и шифрует данные без участия человека.

## Как собрать и запустить (Windows, текущее окружение)

1. Окружение MSVC восстанавливается из дампа `D:\Dev\msvc-env.txt` скриптом `D:\Dev\env.ps1`
   (`CARGO_HOME=D:\Dev\cargo`, `RUSTUP_HOME=D:\Dev\rustup`, `CARGO_TARGET_DIR=D:\Dev\target`).
2. Фронтенд: `npm run build` в каталоге `launcher` (SvelteKit, adapter-static, вывод в `launcher/build`).
3. Сборка приложения со **встроенным** фронтендом:
   `npx tauri build --debug --no-bundle` → `D:\Dev\target\debug\fousbrowser-launcher.exe`.
4. Важно: `cargo build` без Tauri CLI даёт dev-сборку, которая грузит фронтенд с
   `http://localhost:1420`. Без запущенного Vite-сервера окно показывает `ERR_CONNECTION_REFUSED`,
   и любые снимки экрана будут ложными. Для проверок нужен шаг 3.
5. Тесты ядра: `cargo test` (в песочнице сессии `%TEMP%` недоступен дочерним процессам,
   поэтому прогон делается с `TEMP`/`TMP` внутри рабочей области).

## Как проверяется интерфейс и запуск (E2E)

Проверка идёт через **Chrome DevTools Protocol** самой WebView2, а не через координаты и не
через UI Automation: дерево доступности WebView2 строится лениво и даёт ложные «элемент не
найден». Сценарии лежат в `D:\Dev` (вне репозитория, потому что содержат пути этой машины).

1. `D:\Dev\launch.ps1 -Root <каталог> [-EnginePath <браузер>]` — запускает приложение с
   `FOUSBROWSER_HOME`, `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`
   и (для проверок запуска) подменой движка через `FOUSBROWSER_ENGINE_PATH`.
2. `node D:\Dev\run-m3.mjs` — профили: создание, клон, правка, удаление со стиранием,
   блокировка, неверный пароль.
3. `node D:\Dev\run-m5.mjs` — запуск и остановка: расшифровка, старт движка, оформление окна,
   запись данных, шифрование обратно, стирание копии, «остановить все профили».

## Известные ограничения и что улучшать

- **Скорость шифрования при остановке.** Шифрование профиля из 1300 файлов (40 МиБ) занимает
  около 17 секунд: почти всё время уходит на накладные расходы по файлам (создание и проверка
  антивирусом), а не на шифр (замер: 462 МиБ/с). План: шифровать файлы параллельно и
  пропускать неизменённые (индекс по времени и размеру), а в интерфейсе показывать прогресс.
- **Прокси с логином и паролем** пока отказывает в запуске: нужен локальный мост (M6).
- Отладочная сборка оптимизируется (`opt-level = 1`, зависимости — `2`): без этого
  XChaCha20 в dev-сборке работал в сотни раз медленнее.
- `icon.icns` удалён: сборки для macOS не выпускаются, а значок оставался шаблонным.

## Правила работы над проектом

- Коммит после каждого завершённого этапа и после каждой значимой правки: работа не должна
  зависеть от истории переписки.
- Не трогать хранилище сессий агента (список сессий, удаление, fork/resume во время работы) и не
  запускать вторую копию среды в том же рабочем каталоге: единственный известный путь потери
  журнала сессии — внешнее удаление каталога сессии, после которого запись в журнал падает с
  `ENOENT`.
- Не прогонять исходники через PowerShell-командлеты текста без `-Encoding UTF8`: файл
  перекодируется и русский текст в нём портится.
- Все проверки интерфейса — только на сборке со встроенным фронтендом:
  `npx tauri build --debug --no-bundle` (см. ниже).

## Доступ к GitHub

Каталог `C:\Users\user\.ssh` в этой среде исчезает (как и каталоги сессий), поэтому ключ и
`known_hosts` лежат вне профиля пользователя: `D:\Dev\ssh\`. Репозиторий настроен на них:

```
git config core.sshCommand "ssh -i D:/Dev/ssh/fousbrowser_ed25519 -o UserKnownHostsFile=D:/Dev/ssh/known_hosts -o IdentitiesOnly=yes"
```

Host-ключи GitHub в `known_hosts` взяты из `https://api.github.com/meta` и сверены по
отпечаткам (`ssh-keygen -lf`). Публичный ключ, который нужно добавить в GitHub:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIBEsJH2X7DfJJcKmburY3HCxkx47jQbUImXNpmoFoWtU Fousman34@users.noreply.github.com
```
