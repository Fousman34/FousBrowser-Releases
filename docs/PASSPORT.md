# FousBrowser — паспорт проекта

Один файл, чтобы понять проект с нуля: что заказано, как сделано, что уже выпущено,
что осталось и как продолжить работу. Документ рассчитан на то, что его прочитает
другой ассистент (или человек) без доступа к истории переписки.

Дата состояния: **октябрь 2026**. Версия лаунчера: **0.1.1** (0.1.0 выпущена ранее).
Платформа: **только Windows**.

---

## 1. Что это такое в одном абзаце

**FousBrowser — это лаунчер профилей браузера, а не сам браузер.** Отдельное
приложение управляет профилями (создать, клонировать, удалить, запустить,
остановить), хранит их **зашифрованными на диске**, при запуске расшифровывает
профиль во временный каталог, запускает выбранный движок браузера с
`--user-data-dir` на этот каталог, оформляет окно под бренд FousBrowser, а при
остановке шифрует данные обратно и стирает открытую копию. Профили бывают двух
типов: **Normal** (обычный Chromium) и **Antidetect** (движок с подменой
отпечатка). Движки обновляются по двум независимым каналам, причём для
Antidetect **обязательна проверка GPG-подписи** встроенным в лаунчер публичным
ключом.

Ключевое свойство: **без мастер-пароля данные недоступны**. Пароль нигде не
хранится — из него выводится ключ (Argon2id), а всё остальное (метаданные
профилей, содержимое профилей, настройки прокси) лежит на диске только в
зашифрованном виде.

## 2. Требования заказчика (полностью)

### 2.1 Общая идея

- Приложение называется **FousBrowser** и является **лаунчером**, а не браузером:
  «мозг», который запускает «движок». Движок — Chromium (форк или сток).
- Проект для **других пользователей**, а не для одного человека: установка без
  среды разработки (никаких Rust/Node/компиляторов у пользователя), без прав
  администратора, данные в пользовательском каталоге, никаких предустановленных
  профилей, никаких зашитых путей автора.

### 2.2 Мастер-пароль и шифрование

- Мастер-пароль: минимум 12 символов, проверка сложности, **пароль не хранится**.
- Ключ выводится через **Argon2id**.
- Зашифрованы: список профилей, их настройки, содержимое профилей, прокси.
- Схема работы с профилем: на диске — шифр; при запуске — расшифровка во временный
  каталог (или RAM-диск), запуск браузера с `--user-data-dir`; при закрытии —
  шифрование обратно и удаление открытой копии (по возможности затирание).
- После аварийного завершения лаунчера: найти осиротевшие расшифрованные каталоги
  и либо зашифровать, либо удалить (по настройке).

### 2.3 Профили

- Типы: **Normal** и **Antidetect**.
- Действия: создать, удалить (с подтверждением и необратимой очисткой),
  **клонировать** (новое зерно отпечатка), запустить, остановить.
- Отдельная кнопка **«остановить все профили»**.
- **Прокси на профиль**: SOCKS5 / HTTP / HTTPS, с логином и паролем, хранится
  зашифрованным.

### 2.4 Обновления (два независимых канала)

- **Normal** — официальный канал Chromium (совместимый с Omaha / Chrome for Testing).
- **Antidetect** — GitHub Releases вида
  `https://api.github.com/repos/{owner}/{repo}/releases/latest`, с **обязательной
  проверкой GPG-подписи**, публичный ключ хранится в лаунчере.
- Гиты-операции — по предоставленному SSH-ключу.
- Если репозитория нет — создать через
  `gh repo create ... --public --description «FousBrowser Antidetect Releases»`.
- Красивый экран обновления: прогресс-бар с процентами, анимация печатающегося
  кода, журнал в стилизованном терминале, экран «обновление завершено» с кнопкой
  **«Перезапустить»**.

### 2.5 Оформление (важно!)

- Стиль «кодинг/хакер/терминал», тёмная тема (зелёный или циан на чёрном, либо
  фиолетово-синий), моноширинный шрифт (JetBrains Mono / Fira Code).
- **Печатающиеся анимации** с мигающим курсором `_`.
- Плавные переходы между экранами (затухание/сдвиг).
- **Запрещено:** резкие выпадающие меню, стандартные системные тултипы, яркие
  попсовые цвета и градиенты, скруглённые «пузырьковые» элементы.
- Иконки — минималистичные ASCII/линейные. Подсказки печатаются посимвольно рядом
  с элементом.
- Значок приложения — **круглый**, «как у нормальных браузеров», красивый.
- **Никаких упоминаний чужих брендов** (особенно Edge) — ни в интерфейсе, ни в
  коде. Только собственный бренд и своя иконка.
- Название пишется **FousBrowser**, не `FOUSBROWSER` (регистр важен).
- Стартовая страница — минимальная страница FousBrowser с **одной строкой поиска
  Google** и больше ничем.

### 2.6 Распространение

- Упаковка: `.exe`/`.msi` для Windows (ранее упоминались `.dmg`, `.AppImage`,
  `.deb`, но **macOS и Linux исключены заказчиком**).
- Обновления должны работать у всех, публичные GitHub Releases скачиваются без
  авторизации.
- README с установкой под каждую ОС и решением проблем (SmartScreen и т.п.).
- **GitHub Actions**: автоматический релиз по тегу версии.
- Лицензия: **PolyForm Noncommercial License 1.0.0** в корне (`LICENSE`);
  в README указано, что коммерческое использование требует отдельного согласия.

### 2.7 Дополнительные указания, полученные по ходу работы

- Общаться **по-русски**; не молчать подолгу — заказчик воспринимает тишину как
  зависание; сообщать, что делается.
- **Не переписывать проект с нуля** — работы уже много сделано.
- Не тратить время на Linux (в итоге — исключить Linux и macOS полностью).
- Проект уже создан на GitHub; доступ по SSH работает.

## 3. Технологии и почему так

| Часть | Выбор | Причина |
|---|---|---|
| Оболочка приложения | **Tauri 2** | Нативный `.exe`/`.msi` без прав администратора, данные в `%APPDATA%`, системный WebView2 уже есть в Windows |
| Ядро | **Rust** | Шифрование и работа с процессами должны быть быстрыми и безопасными по памяти |
| Интерфейс | **SvelteKit + Svelte 5 (runes)**, adapter-static | Маленький бандл, тонкая реактивность, легко делать печатающиеся анимации |
| Шифрование | `argon2`, `chacha20poly1305`, `hkdf`, `sha2`, `zeroize`, `rand` | Проверенные реализации RustCrypto; в dev-профиле повышен `opt-level`, иначе шифрование в отладочной сборке медленное |
| Проверка подписи | `sequoia-openpgp` (только `crypto-rust`, без системного gpg) | У пользователя не должно быть установлено ничего лишнего |
| Сеть | `ureq` (rustls) | Проверка обновлений и загрузка движков |
| Архивы | `zip` | Распаковка сборок движка |
| Асинхронность | `tokio` | Прокси-мост, фоновые задачи |
| Сборка релиза | GitHub Actions, `tauri-action` | Тег → установщики и релиз без ручных шагов |

## 4. Как устроено внутри

### 4.1 Где лежат данные пользователя

```
%APPDATA%\FousBrowser\            (переопределяется переменной FOUSBROWSER_HOME)
├── vault\
│   ├── vault.json                заголовок: соль, параметры Argon2id, vault_id,
│   │                             счётчик неудачных попыток (открытым текстом —
│   │                             иначе нечего проверять пароль)
│   ├── metadata.enc              список профилей, настройки, прокси (шифр)
│   ├── profiles\<uuid>\...       содержимое профилей (каждый файл — контейнер)
│   ├── tmp\<uuid>\...            расшифрованная копия, пока браузер работает
│   └── index.json                журнал запущенных профилей (открытым текстом:
│                                 uuid, pid, каталог, состояние, версия движка, путь
│                                 к исполняемому файлу) — нужен для восстановления
│                                 после краха
└── browsers\
    ├── normal\<версия>\...       движок Normal
    ├── antidetect\<версия>\...   движок Antidetect
    ├── normal\current.json       указатель: какая версия используется
    └── antidetect\current.json
```

Временный каталог и каталог движков лежат рядом с хранилищем, а не в системе.

### 4.2 Шифрование (точно)

- Ключ: **Argon2id**, 256 МиБ памяти, t=3, p=4, соль из `vault.json`.
- Подключи: **HKDF-SHA256** — отдельный ключ метаданных и **отдельный ключ на
  каждый профиль**.
- Шифр: **XChaCha20-Poly1305**, 24-байтовый случайный nonce на блок, формат
  контейнера `nonce || ciphertext+tag`.
- **AAD** привязывает данные к контексту: назначение, версия формата, `vault_id`,
  путь внутри профиля, номер блока, длину. Поэтому нельзя переставить блоки или
  подменить путь.
- Формат файлового контейнера профиля: сигнатура `FBX1`, версия, тип (файл или
  ссылка), размер блока 1 МиБ, длина открытого текста; **последняя запись
  подтверждает конец и длину**, поэтому обрезанный контейнер не примут за целый.
- Замена каталога атомарная: расшифровка идёт в `<uuid>.staging`, затем
  переименование, на время остаётся `.previous` для отката.
- **«Исчезнувшие» файлы.** Браузер удаляет часть файлов во время работы. Если файл
  пропал в момент шифрования, он пропускается и считается в статистике
  (`vanished`). Но если файл **занят** (не удалось прочитать), шифрование
  **прерывается** — молча терять данные нельзя.

### 4.3 Жизненный цикл профиля

1. **Запуск.** Проверяется, что движок есть (иначе понятная ошибка), расшифровка
   `profiles/<uuid>` в `tmp/<uuid>`, при необходимости поднимается локальный
   прокси-мост, движок стартует с `--user-data-dir=<tmp>`, в журнал пишется
   `pid` и путь к исполняемому файлу.
2. **Оформление окна.** Отдельный поток ждёт появления главного окна и:
   - переименовывает его в `FousBrowser — <имя профиля>` (из заголовка движка
     вырезается название чужого вендора, которое читается из ресурсов самого
     файла движка — так мы не зашиваем список имён);
   - ставит нашу иконку (`WM_SETICON`, значок берётся из ресурсов лаунчера).
3. **Остановка.** Сначала **вежливо**: `WM_CLOSE` главному окну (ровно то, что
   делает пользователь, нажимая крестик). `taskkill` без `/F` окно **не
   закрывает** — проверено на живом процессе. Если движок не ответил за 12
   секунд — принудительное завершение дерева процессов.
4. **Шифрование обратно.** `tmp/<uuid>` упаковывается в `profiles/<uuid>`,
   открытая копия стирается, журнал очищается.
5. **«Остановить все профили».** То же для всех запущенных, с отчётом по каждому
   (сколько зашифровано, где не получилось).

### 4.4 Прокси

Прокси-сервер **не передаётся движку напрямую**: логин и пароль прокси не должны
попадать в командную строку процесса (её видно в диспетчере задач). Поэтому:

- лаунчер поднимает **локальный SOCKS5-сервер** на `127.0.0.1:<случайный порт>`;
- движок получает только `socks5://127.0.0.1:<порт>`;
- мост сам ходит к настоящему прокси: upstream SOCKS5 (с авторизацией RFC 1929)
  или HTTP CONNECT (заголовок `Proxy-Authorization: Basic ...`);
- мост живёт ровно столько же, сколько профиль.

Известное ограничение: схема `https` сейчас устанавливает соединение как обычный
HTTP CONNECT (без TLS до самого прокси).

### 4.5 Восстановление после краха

При разблокировке хранилища лаунчер разбирает журнал:

- если в журнале есть процесс, он завершается **только при совпадении пути к
  исполняемому файлу** с записанным (по одному номеру процесса убивать нельзя —
  номер мог достаться чужой программе);
- путь из журнала обязан находиться внутри `vault\tmp` (защита от подмены);
- расшифрованные данные возвращаются в контейнеры;
- поведение для «осиротевших» каталогов настраивается: зашифровать (по умолчанию)
  или удалить.

### 4.6 Обновления

Два независимых канала.

| Канал | Источник | Проверка |
|---|---|---|
| **Normal** | манифест Chrome for Testing (`googlechromelabs.github.io`), ссылка на архив в официальном хранилище | TLS + проверка структуры архива. **Официальный источник контрольных сумм не публикует** — это его свойство, зафиксировано в документации |
| **Antidetect** | `api.github.com/repos/Fousman34/FousBrowser-Releases/releases`, теги `antidetect-v*` | **GPG-подпись списка сумм** встроенным ключом → затем **SHA-256 архива** |

Порядок установки: скачать в `browsers/<канал>/.staging` → проверить подпись и
сумму → распаковать с запретом небезопасных путей (`../`) → перенести каталог на
место версии → переписать указатель `current.json`. **Работающая версия не
трогается до последнего шага**, прежняя версия остаётся на диске для отката.

Тонкость, которую обязательно надо знать: **`sequoia-openpgp` сама не отвергает
неподтверждённую подпись** — решение принимает проверяющий. Если в обработчике
`check` просто вернуть «ок», подделанные данные и подпись чужим ключом пройдут
проверку. В нашем коде `check` требует **хотя бы одну подпись, подтверждённую
встроенным ключом**, и это закрыто тестами.

Загрузка: **с докачкой**. Обрыв соединения не считается окончательной ошибкой:
файл докачивается заголовком `Range` до шести попыток. Это не теория — первый
вариант с общим таймаутом в 60 секунд обрывал загрузку 185 МиБ на 15 МиБ.

### 4.7 Полные права доступа

Лаунчер запрашивает **только** пользовательские каталоги. Прав администратора не
требуется: и `%APPDATA%`, и `%LOCALAPPDATA%` доступны обычному пользователю.

## 7. Что осталось доделать

### 7.1 Обязательное (мелкое)

1. **Статус движка не обновляется после установки при работающем лаунчере.**
   Если поставить движок из панели обновлений, карточка профиля продолжает
   говорить «движок не установлен» до перезапуска приложения. Нужно после
   успешной установки перечитать состояние движков (или отправить событие в
   интерфейс). Файл: `launcher/src-tauri/src/commands.rs` (команда
   `update_install`) и `launcher/src/lib/components/UpdatePanel.svelte`.
2. **Проверка на чужой машине** («чистая» Windows без Chrome и без среды
   разработки): скачать `.exe` из релиза, установить, создать хранилище, поставить
   движок Antidetect, запустить профиль. На этой машине всё проверено, на чужой —
   нет.
3. **Удалить устаревший релиз `v0.1.0`** (кнопками на GitHub), чтобы не путались
   две версии — установщики 0.1.0 собраны до исправления докачки.

### 7.2 Известные ограничения (задокументированы, не баги)

- **Движок Antidetect — зеркало, не собственный форк.** Это подписанная сборка
  ungoogled-chromium с патчами подмены отпечатка (проект fingerprint-chromium).
  Собственный форк Chromium (Фаза B) — отдельный проект на месяцы: около 100 ГБ
  исходников, часы сборки; на бесплатных раннерах GitHub это невозможно (лимиты
  диска и времени).
- **Канал Normal без контрольных сумм** — официальный источник их не публикует.
- **Прокси со схемой `https`** соединяется как обычный HTTP CONNECT (без TLS до
  прокси).
- **Скорость шифрования при остановке** профиля: узкое место — накладные расходы
  на 1300+ файлов, а не шифр. Идеи: параллельная упаковка и пропуск неизменённых
  файлов; прогресс шифрования в интерфейсе.
- **Самообновление лаунчера** не реализовано (обновляются только движки);
  заготовка канала есть в `updater`.
- macOS и Linux исключены заказчиком: кода под другие системы в проекте **не
  осталось** (ни веток `cfg`, ни путей `/proc`, ни платформы Linux в сервисе
  обновлений).


Движок выпускается так: подготовить каталог
`browsers/antidetect/<версия>/` с `release.json`, `SHA256SUMS` и **подписанным**

скачает сборку проекта-основы, проверит подпись нашим кодом, сверит SHA-256,
проверит наличие исполняемого файла в архиве и опубликует релиз.

### 8.4 Правила работы (выучено на ошибках)

- **Не прогонять исходники через текстовые командлеты PowerShell 5.1** — кириллица
  портится (уже ломался `flags.rs`). Правки русских строк — только через `write`
  или Python, читающий/пишущий UTF-8.
- `$home` и `$HOME` в PowerShell — автоматические переменные, присваивать нельзя.
- Скрипты, печатающие русский текст в консоль, показывают крякозябры — это
  особенность консоли; содержимое файлов при этом верное. Проверять через Python.
- `gpg` из Git для Windows (MSYS) требует **прямых слэшей** в путях и
  `--homedir /d/Dev/gnupg`.
- **Побайтовые файлы** (суммы, подписи, ключи) помечены в `.gitattributes` как
  нетекстовые: иначе на Windows-раннере checkout меняет LF на CRLF и проверка
  подписи падает при зелёных локальных тестах (так и было).
- **Коммитить после каждого этапа** и обновлять `docs/PROGRESS.md`; заказчик
  возвращается к проекту после пауз, состояние должно читаться из репозитория.
- Не трогать сессии и настройки самого DSH; не запускать второй экземпляр.
- В интерфейсе и текстах **не упоминать чужие бренды** — ни Edge, ни Chrome
  (Chrome допустим только как обозначение внутреннего движка в технической
  документации).
